CASE STUDY 01 POSTGRESQL • POWER BI • 45,000+ RECORDS

Retail Sales Performance & Customer Lifetime Value Engine

In transactional retail environments, evaluating raw order volume without cohort segmentation creates blind spots. This investigation unified 45,000+ orders across four relational tables (Customers, Orders, Order Items, Products) to evaluate repeat purchasing patterns, regional return discrepancies, and customer lifetime spend.

  • Constructed PostgreSQL Common Table Expressions (CTEs) utilizing window functions (ROW_NUMBER(), DENSE_RANK()) to isolate recency intervals and tier buyers by cumulative revenue.
  • Engineered a Star Schema in Power BI with a central Fact_Sales linked to four dimension tables, avoiding wide unnormalized tables and keeping VertiPaq memory footprint low.
  • Authored dynamic DAX measures for Month-over-Month (MoM) revenue variance and Average Order Value (AOV) across fiscal quarters.

WITH customer_orders AS (
    SELECT 
        c.customer_id, c.customer_name, c.state,
        o.order_id, o.order_date,
        SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS order_val,
        ROW_NUMBER() OVER (
            PARTITION BY c.customer_id 
            ORDER BY o.order_date DESC
        ) AS recency_rank
    FROM customers c
    JOIN orders o ON c.customer_id = o.customer_id
    JOIN order_items oi ON o.order_id = oi.order_id
    WHERE o.order_status = 'Completed'
    GROUP BY c.customer_id, c.customer_name, c.state, o.order_id, o.order_date
)
SELECT 
    customer_name, state, COUNT(order_id) AS orders,
    ROUND(SUM(order_val)::numeric, 2) AS lifetime_spend,
    DENSE_RANK() OVER (ORDER BY SUM(order_val) DESC) AS rank
FROM customer_orders
GROUP BY customer_id, customer_name, state
ORDER BY lifetime_spend DESC LIMIT 5;
