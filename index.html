01. Retail Customer Lifetime Spend & Recency Analysis

POSTGRESQL • POWER BI • 45,000+ TRANSACTION ROWS

When retail data sits scattered across disparate order line items and customer records, top-line revenue hides customer attrition. This project joined 45,000+ order records across four relational tables to isolate repeat-buyer frequency and evaluate return rates by region.

Methodology & Engineering Choices

Rather than writing nested subqueries that require multiple table passes, I used Common Table Expressions (CTEs) paired with ROW_NUMBER() partitioned by customer to identify each account's latest order date, alongside DENSE_RANK() to create clean spend tiers without skipped ranks.

  • Modeled a clean Star Schema in Power BI with Fact_Sales linked to four dimension tables, preventing table bloat and optimizing DAX execution.
  • Wrote custom DAX time-intelligence measures for Month-over-Month (MoM) revenue growth and dynamic Average Order Value (AOV).
  • Identified that 62% of product returns originated from two specific fulfillment centers, highlighting localized packaging issues rather than catalog defect.

WITH customer_orders AS (
    SELECT 
        c.customer_id, c.customer_name, c.state,
        o.order_id, o.order_date,
        SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS order_val,
        ROW_NUMBER() OVER (
            PARTITION BY c.customer_id 
            ORDER BY o.order_date DESC
        ) AS recency_rank
    FROM customers c
    JOIN orders o ON c.customer_id = o.customer_id
    JOIN order_items oi ON o.order_id = oi.order_id
    WHERE o.order_status = 'Completed'
    GROUP BY c.customer_id, c.customer_name, c.state, o.order_id, o.order_date
)
SELECT 
    customer_name, state, COUNT(order_id) AS orders,
    ROUND(SUM(order_val)::numeric, 2) AS lifetime_spend,
    DENSE_RANK() OVER (ORDER BY SUM(order_val) DESC) AS rank
FROM customer_orders
GROUP BY customer_id, customer_name, state
ORDER BY lifetime_spend DESC LIMIT 5;
-- Total Revenue
Total Revenue = 
SUMX(Fact_Sales, Fact_Sales[Quantity] * Fact_Sales[UnitPrice] * (1 - Fact_Sales[Discount]))

-- Prior Month Revenue
Prior Month Revenue = 
CALCULATE([Total Revenue], DATEADD(Dim_Date[Date], -1, MONTH))

-- MoM Revenue Growth %
MoM Revenue Growth % = 
DIVIDE([Total Revenue] - [Prior Month Revenue], [Prior Month Revenue], 0)

-- Average Order Value
Average Order Value = 
DIVIDE([Total Revenue], DISTINCTCOUNT(Fact_Sales[OrderID]), 0)

02. Subscriber Attrition & Contract Risk Segmentation

PYTHON • PANDAS • SEABORN • 7,043 RECORDS

Exploratory analysis of 7,043 telecom customer accounts. The objective was to diagnose behavioral drivers behind subscriber churn and evaluate whether contract type or billing methods had stronger correlation with account cancellation.

Data Hygiene & Diagnostic Findings

The raw file had hidden whitespace in the total_charges column causing string conversion errors. Rather than dropping rows blindly, I examined the records and discovered they exclusively belonged to new accounts with tenure == 0. Imputing zero charges preserved valid customer cohorts.

  • Calculated bivariate churn rates across contract commitments, discovering that month-to-month subscribers churn at 42.7%, representing 88% of all churned accounts.
  • Customers on two-year agreements exhibited an attrition rate of just 2.83% at similar monthly price points.
  • Documented actionable intervention points: accounts transitioning past month 4 showed a 60% reduction in churn likelihood.

03. Retail Inventory Tracking & Reorder Discrepancy Model

ADVANCED EXCEL • 350+ UNIQUE SKUS

Replaced a paper-based inventory log for a multi-category store with an automated workbook featuring dynamic lookup logic, multi-condition aggregation, and input validation to eliminate manual entry errors.

Stockouts were frequently caused by transcription errors and lack of dynamic reorder warnings. By structuring a two-table workbook with strict data validation boundaries, inventory variance was reduced to zero across 350+ items.

  • Used XLOOKUP over VLOOKUP to allow bidirectional searches and avoid column-insertion breakage.
  • Configured dynamic multi-condition SUMIFS to aggregate store inventory by category and availability status.
  • Built Pivot Tables with Slicers for quick category filtering during supplier reorder meetings.
Core Formula Logic 
-- 1. Dynamic Stock Lookup
=XLOOKUP(A2, Catalog!A:A, Catalog!C:C, "Not Found", 0)

-- 2. Threshold Reorder Status
=IF(Current_Stock <= Safety_Stock, "REORDER REQUIRED", "STABLE")

-- 3. Multi-Condition Aggregation
=SUMIFS(Inventory[Qty], Inventory[Cat], "Electronics", Inventory[Status], "In Stock")

Data Architecture & Schemas

RELATIONAL PATTERNS

Star Schema vs. Flat Tables

In Power BI, wide single-table extracts create redundant data, slow down DAX calculations, and complicate period-over-period logic. I design clean dimensional models separating transactional facts from descriptive entities.

Fact Table: Fact_Sales [Order_ID, Customer_ID, Product_ID, Date_Key, Qty, Unit_Price, Discount]
├── Dim_Customer: [Customer_ID, Name, City, State, Cohort_Date]
├── Dim_Product: [Product_ID, Name, Category, Cost_Price]
├── Dim_Date: [Date_Key, Date, Month, Quarter, Year, Fiscal_Period]
└── Dim_Region: [Region_ID, Hub_Name, State, Zone]

Relational Query Principles

My approach to database extraction prioritizes query readability, index awareness, and defensible logic:

  • CTEs over Subqueries: Break complex multistage calculations into named, readable logical blocks.
  • Explicit JOINs: Always use explicit INNER JOIN or LEFT JOIN with clear ON clauses; avoid implicit Cartesian joins.
  • Filter Before Aggregation: Use WHERE clauses early to trim record volume before evaluating GROUP BY and HAVING.
  • Deterministic Ranking: Use DENSE_RANK() when tied values must preserve continuous tiers without leaving numeric gaps.
