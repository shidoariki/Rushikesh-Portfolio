1. Retail Sales & Customer Performance Dashboard

Dataset: 45,000+ e-commerce transaction records across 4 relational tables (Customers, Orders, Order_Items, Products).

PostgreSQL Query: Customer Lifetime Value (CLV) & Recency Analysis

WITH customer_orders AS (
    SELECT 
        c.customer_id,
        c.customer_name,
        c.state,
        o.order_id,
        o.order_date,
        SUM(oi.quantity * oi.unit_price * (1 - oi.discount)) AS order_value,
        ROW_NUMBER() OVER (
            PARTITION BY c.customer_id 
            ORDER BY o.order_date DESC
        ) AS recency_rank
    FROM customers c
    INNER JOIN orders o ON c.customer_id = o.customer_id
    INNER JOIN order_items oi ON o.order_id = oi.order_id
    WHERE o.order_status = 'Completed'
    GROUP BY c.customer_id, c.customer_name, c.state, o.order_id, o.order_date
),
customer_summary AS (
    SELECT 
        customer_id,
        customer_name,
        state,
        COUNT(order_id) AS total_orders,
        ROUND(SUM(order_value)::numeric, 2) AS lifetime_spend,
        ROUND(AVG(order_value)::numeric, 2) AS average_order_value,
        MAX(CASE WHEN recency_rank = 1 THEN order_date END) AS last_order_date
    FROM customer_orders
    GROUP BY customer_id, customer_name, state
)
SELECT 
    customer_id,
    customer_name,
    state,
    total_orders,
    lifetime_spend,
    average_order_value,
    last_order_date,
    DENSE_RANK() OVER (ORDER BY lifetime_spend DESC) AS spend_rank
FROM customer_summary
ORDER BY lifetime_spend DESC
LIMIT 20;

Key Power BI DAX Measures

-- Total Revenue
Total Revenue = 
SUMX(Fact_Sales, Fact_Sales[Quantity] * Fact_Sales[UnitPrice] * (1 - Fact_Sales[Discount]))

-- Month-over-Month (MoM) Revenue Growth %
Revenue Prior Month = 
CALCULATE([Total Revenue], DATEADD(Dim_Date[Date], -1, MONTH))

MoM Revenue Growth % = 
DIVIDE([Total Revenue] - [Revenue Prior Month], [Revenue Prior Month], 0)

-- Return Rate %
Return Rate = 
DIVIDE(
    CALCULATE(COUNTROWS(Fact_Sales), Fact_Sales[OrderStatus] = "Returned"),
    COUNTROWS(Fact_Sales),
    0
)

2. Customer Churn Exploratory Analysis (Python)

Dataset: 7,043 subscriber records. Focus on data cleaning and discovering correlation between contract types and attrition.

Pandas Data Cleaning & Segmentation Workflow

import pandas as pd
import numpy as np

# Load dataset
df = pd.read_csv("telecom_churn.csv")

# 1. Clean column headers
df.columns = df.columns.str.strip().str.lower().str.replace(' ', '_')

# 2. Convert total_charges to numeric, filling whitespace for tenure == 0 with 0
df['total_charges'] = pd.to_numeric(df['total_charges'].str.strip(), errors='coerce').fillna(0)

# 3. Standardize boolean/categorical flags
df['senior_citizen'] = df['senior_citizen'].map({1: 'Yes', 0: 'No'})

# 4. Segment churn by contract type
contract_churn = df.groupby('contract')['churn'].value_counts(normalize=True).unstack() * 100
print(contract_churn)
# Insight: Month-to-month contracts had ~42.7% churn vs. < 3% for two-year contracts.

3. Technical Interview Defense Q&A

Q: What is the difference between WHERE and HAVING in SQL?
The WHERE clause filters individual rows before grouping. The HAVING clause filters aggregated groups after the GROUP BY evaluation. For example, WHERE order_status = 'Completed' filters rows before calculating sums, while HAVING SUM(order_value) > 50000 filters only groups meeting the threshold.
Q: Why did you use DENSE_RANK() instead of ROW_NUMBER() in your SQL query?
ROW_NUMBER() assigns strictly sequential numbers, breaking ties arbitrarily. DENSE_RANK() assigns identical ranks to tied customer spending figures without skipping numbers, ensuring fair customer tier classification.
Q: How did you design your Power BI data model?
I constructed a Star Schema with one central Fact_Sales table connected to 4 dimension tables (Dim_Customer, Dim_Product, Dim_Date, Dim_Region) via 1-to-many relationships. This prevents redundant columns, minimizes memory usage in VertiPaq, and keeps DAX filters fast.
Q: How do you handle missing values in data cleaning?
I first analyze whether missingness is random or systematic. For example, in the churn dataset, empty total charge fields corresponded strictly to newly registered customers with 0 tenure, so imputing zero made factual sense rather than deleting the rows.
